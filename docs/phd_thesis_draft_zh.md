## 二、摘要草稿

分子胶类小分子通过诱导或稳定蛋白质之间的非天然相互作用，在靶向蛋白降解、转录调控与难成药靶点干预等领域展现出重要潜力。然而，与传统酶抑制剂和经典 PROTAC 分子相比，分子胶的发现过程高度依赖三元复合物的构象适配、界面重塑与局部化学环境匹配，存在候选空间大、结构判据分散、实验验证成本高以及跨软件工作流割裂等问题。现有研究虽然分别提供了蛋白口袋分析、分子对接、蛋白质对接、相互作用识别和静电势计算等工具，但尚缺乏一个围绕分子胶发现任务组织的、可直接支持“识别-建模-评估-解释”闭环的一体化计算框架。

本研究面向分子胶发现的关键需求，提出并实现了一套基于 PyMOL 环境的结构计算与可视化集成框架 GLINT。该框架以分子胶诱导三元复合物为中心对象，将 G-loop/G-motif 结构模板匹配、蛋白表面相似性与互补性分析、网格化口袋检测、蛋白-配体及蛋白-蛋白相互作用识别、约束驱动的 HADDOCK3 三元复合物建模、配体静电互补分析以及多维度三元复合物综合评分等功能统一到同一工作流中，从而形成面向候选底物发现、命中识别、复合物评价和先导优化的连续分析链路。

在方法上，本文围绕分子胶发现的结构判据构建了多个可组合的计算模块。首先，针对 CRBN 相关底物识别需求，设计了基于八残基 Cα 几何模板的 G-loop 结构检索方法，支持插入码、替代构象和模板别名映射，能够以结构而非单纯序列为核心识别潜在可招募底物。其次，提出面向分子胶场景的三元复合物评价特征体系，将 MG-E3、MG-POI 与 E3-POI 三个界面的埋藏表面积、接触计数、链间最小距离、配体理化参数以及三元几何构型统一编码为可计算特征，用于刻画三元体系的界面平衡性与构象合理性。再次，本文构建了一个以研究任务为中心的软件集成层，通过统一接口协调 AutoDock Vina、HADDOCK3、APBS/PDB2PQR、FoldX 等外部科学计算工具，并在缺失依赖时提供回退策略或降级路径，从而显著降低复杂结构分析流程的使用门槛。

系统实现方面，GLINT 采用模块化架构，将核心算法、外部引擎封装、批处理分析与图形界面解耦。平台兼容 macOS、Windows 与 Linux，并通过 Qt 适配层与环境检测模块处理 PyMOL 嵌入式 Python、Conda 环境与多版本图形库之间的兼容性问题。实验部分以已知分子胶相关复合物和案例结构为对象，对 G-loop 识别、口袋性质分析、界面相互作用检测、三元复合物建模与综合评价流程进行了验证。结果表明，该框架能够在统一环境下完成从候选结构筛选到三元复合物解释的多步骤分析，并为分子胶发现中的底物招募假设生成、界面优化和构效关系分析提供可操作的计算支持。

本研究的主要贡献在于：提出了一个面向分子胶发现任务组织的结构计算框架；构建了适配三元复合物机制的多模块特征体系与评价流程；实现了多种成熟科研工具的稳定集成与可视化联动。相关工作为分子胶发现中的结构表征、机制解释和先导优化提供了新的方法基础，也为后续引入机器学习模型、开展大规模候选筛选和构建专用数据库奠定了工程与方法学基础。

关键词：分子胶；靶向蛋白降解；三元复合物；结构生物信息学；PyMOL 插件；蛋白-蛋白相互作用

## 四、研究背景与问题定义

### 4.1 研究背景

分子胶不同于传统占位型小分子。其活性往往来源于对蛋白质互作网络的重塑，即通过小分子介导 E3 连接酶与底物蛋白形成稳定或瞬态的三元复合物。此类机制决定了分子胶发现不再只是“寻找一个高亲和力口袋”，而是同时涉及配体与两个生物大分子之间的多方匹配问题，包括局部结构基序是否可招募、蛋白表面是否互补、配体是否能够在空间上桥接两侧界面，以及新形成的蛋白-蛋白界面是否具有足够的稳定性和选择性。

### 4.2 现有方法的不足

现有工作通常将对接、口袋分析、相互作用分析和静电势计算分散在不同软件中完成，导致以下问题：

1. 缺乏针对分子胶场景定义的统一分析对象。
2. 三元复合物关键判据难以在同一坐标系下联合解释。
3. 外部科学软件安装复杂，跨平台复现成本高。
4. 研究者往往需要在命令行工具、脚本环境和可视化软件之间频繁切换。

### 4.3 本文拟解决的核心问题

本文尝试解决如下三个问题：

1. 如何将分子胶发现过程中的核心结构判据形式化为可计算、可组合的分析模块。
2. 如何在保持科研软件可信度的前提下，将多个成熟工具整合为可复用的一体化流程。
3. 如何在三维可视化环境中实现“计算结果-结构解释-候选设计”之间的闭环。

## 五、论文总体思路与技术路线

本文的总体思路是：围绕分子胶三元复合物形成这一核心事件，把底物可招募性、配体可桥接性、界面可稳定性和结果可解释性拆解为多个可计算子任务，再通过统一的数据结构、命令接口和图形界面将其连接起来。

可以将技术路线概括为五步：

1. 候选底物识别：利用 G-loop/G-motif 结构模板匹配识别潜在可招募蛋白。
2. 结合环境分析：利用口袋检测、蛋白表面性质与静电分析评估局部可容纳性。
3. 复合物建模：结合 AutoDock Vina 与 HADDOCK3 对配体姿态和三元复合物进行约束建模。
4. 复合物评价：从界面面积、接触模式、理化性质和三元几何构型等维度进行综合评价。
5. 结果解释与优化：通过相互作用图谱、表面互补性、突变分析和可视化联动支持先导优化。

如果需要画论文总图，可以用“数据输入层-结构分析层-建模层-评价层-可视化与交互层”的五层架构图。

## 八、第三章正文草稿：框架设计

### 3.1 总体设计目标

本文设计 GLINT 框架的核心目标并非开发一个泛化的分子建模平台，而是构建一个面向分子胶研究问题的专用结构分析环境。围绕这一目标，系统需满足四项要求：第一，能够描述分子胶发现中关键的三元复合物结构关系；第二，能够将口袋、界面、静电与构象等异构信息纳入同一工作流；第三，能够在科研常用的三维分子可视化环境中直接使用；第四，能够兼容不同操作系统和多类外部科学计算依赖。

### 3.2 系统分层架构

GLINT 采用分层式架构。底层为外部科学计算引擎与基础数据处理层，包括 Vina、HADDOCK3、APBS/PDB2PQR、FoldX 以及 NumPy、SciPy、RDKit 等基础库；中间层为任务导向的分析模块层，包括 G-loop 基序检测、口袋检测、表面相似性分析、相互作用分析、突变分析、三元复合物评价等；上层为 PyMOL 命令接口与图形交互层，用于实现结果展示、参数输入和流程组织。该架构实现了算法逻辑、依赖封装和可视化交互之间的职责分离。

### 3.3 核心分析对象的统一定义

不同于传统仅围绕单一蛋白或单一配体的分析模式，本文将“分子胶诱导三元复合物”定义为核心分析对象。围绕该对象，系统建立了三类关键实体：蛋白链实体、配体实体和界面实体。其中，界面实体不仅包括蛋白-配体界面，也包括配体参与重塑后的蛋白-蛋白界面。基于这一抽象，后续模块能够对 MG-E3、MG-POI 与 E3-POI 三类关系进行统一编码与比较。

### 3.4 工作流组织策略

系统并未将所有模块简单堆叠，而是按照研究任务组织为五类功能分组：Target Discovery、Hit Identification、Lead Optimization、Ternary Evaluation 和 Visualization。该组织方式与分子胶研究的实际流程一致，有利于用户从候选底物筛选逐步推进到复合物建模和先导优化，也便于将不同分析结果回投到三维结构解释中。

### 3.5 设计原则

系统实现遵循以下原则：一是优先复用经过社区验证的上游科研工具，不重新实现其底层物理求解器；二是对关键分析步骤保留本地轻量回退方案，以提高环境适应性；三是将算法结果设计为可解释特征，而非仅输出黑箱评分；四是尽量保持 PyMOL 内部操作闭环，减少研究者的工具切换成本。

## 九、第四章正文草稿：关键方法与算法实现

### 4.1 G-loop 结构模板匹配方法

针对 CRBN 相关分子胶常依赖底物局部环区构象适配的问题，本文设计了 G-loop 结构模板匹配模块。该模块以内置模板为参照，将模板和目标结构中的连续八个残基 Cα 坐标提取出来，通过几何对齐与 RMSD 计算评价目标片段是否具备与已知底物相近的局部构象。与单纯序列模体搜索不同，该方法强调结构等价性，因此更适用于存在低序列同源但构象保守的候选底物识别。

在实现上，模块支持多套模板定义与别名映射，能够处理插入码残基、替代构象以及不同 PDB 编号对应的 CRBN 关键位点编号差异。默认采用 3.5 Å 的 RMSD 阈值，并提供第六位残基是否要求 Gly 的可选过滤策略。该设计使得模块既可以服务于标准化筛选，也适用于探索性分析。由于输出结果兼容后续残基高亮模块，因此识别出的候选片段可以直接映射回 PyMOL 结构界面，实现“搜索-定位-解释”的连续使用体验。

### 4.2 网格化口袋检测与理化性质计算

为了评估潜在配体结合环境，本文实现了一个纯 Python 的蛋白口袋检测模块。该模块基于三维规则网格展开，通过在蛋白包围盒内生成格点、标记被原子范德华半径与探针球占据的区域、再对外部溶剂可及区域进行 flood fill 标记，最终将“未被占据且不与边界连通”的连通区域视为候选腔体。该方法无需依赖外部口袋软件，适合在插件环境中稳定运行。

在口袋分析阶段，系统进一步对体积、表面积、埋藏深度、开口大小、球形度、溶剂可及性等几何性质进行计算，并结合氨基酸理化类别统计疏水性、极性、电荷性、芳香性以及氢键供受体能力，形成口袋多维描述向量。随后通过最小体积、最小深度和最大溶剂暴露度等阈值进行筛选，从而减少浅表凹陷和无效空腔的干扰。该模块为分子胶结合位点的可容纳性分析提供了局部环境依据。

### 4.3 蛋白表面相似性与互补性分析

考虑到分子胶诱导复合物的形成不仅依赖局部口袋，也依赖蛋白表面之间的几何和化学匹配，本文进一步设计了受 MaSIF 思想启发的表面分析模块。系统首先生成表面网格，并为每个表面点计算法向量、曲率、shape index、curvedness 等几何特征；同时结合静电势、疏水性以及氢键供受体密度等信息生成化学特征。随后，将局部表面组织为 patch，并通过均值特征或直方图特征比较不同结构之间的表面相似度。

在互补性分析中，系统从界面接触区域出发，评估形状互补、电荷互补和疏水互补程度，并结合界面面积、接触数、间隙体积和最小距离等指标形成整体互补评分。相较于只比较点对点距离的粗粒度做法，该设计更能反映分子胶诱导界面是否具备稳定装配的条件。

### 4.4 相互作用检测与界面解析

为了增强结构解释能力，本文构建了蛋白-配体、蛋白-蛋白和原子对级别的相互作用识别模块。该模块支持氢键、盐桥、疏水接触、π-π 堆积、阳离子-π、卤键以及水介导相互作用等多类关系。实现上采用双引擎策略：当 RDKit 可用时，使用其化学信息增强判定准确性；在依赖受限时，则退回基于距离和角度规则的纯 Python 实现。两种模式共享统一输出格式，确保上层可视化与后续统计分析逻辑保持一致。

对于分子胶研究而言，这一模块的意义在于能够将“复合物是否合理”具体解释为“哪些残基和官能团在何种几何条件下形成了哪些关键相互作用”。这有助于从经验观察转向结构证据驱动的先导优化。

### 4.5 约束驱动的三元复合物建模方法

由于分子胶诱导复合物通常涉及两个蛋白和一个小分子，单纯分子对接难以完整描述其构象形成过程。为此，本文将 HADDOCK3 封装为约束驱动的三元建模模块。用户只需给定受体和配体的活性残基列表，系统便可自动生成 active/passive restraint 文件和简化的 AMBIG 约束，进一步构建包含拓扑构建和刚体优化的最小工作流，并在执行完成后自动收集模型、合并为多模型 PDB 以载入 PyMOL。

这一设计的关键不在于重新发明蛋白对接算法，而在于将复杂的约束准备、命令调用、文件组织和结果回传流程标准化。对分子胶研究者而言，这种“最小可用封装”显著降低了使用 HADDOCK3 建模三元复合物的门槛。

### 4.6 三元复合物综合评价特征体系

本文进一步构建了面向三元复合物的综合评价模块。该模块定义了统一的数据结构，对原子、链、界面、配体与几何信息进行分层表示。在界面层面，系统计算 MG-E3、MG-POI 与 E3-POI 三类界面的埋藏表面积，以及 4.5 Å 和 5.0 Å 阈值下的接触计数与最小链间距离；在配体层面，提取分子量、LogP、TPSA、可旋转键数、氢键供受体数、Fsp3 与环系数量等性质；在几何层面，计算三方质心关系、中心偏移和夹角等描述符。

与传统仅依赖单一分值的评价方式不同，该模块强调多维分解与可解释性。一方面，研究者可以观察某个候选构型在界面面积上是否充足、在几何上是否过于拉伸或折叠；另一方面，也可以分析配体的理化性质是否偏离合理范围。该设计为后续机器学习建模或规则筛选提供了结构化输入特征。

### 4.7 分子胶设计辅助分析

在上述基础上，系统还实现了面向设计优化的辅助模块，包括 G-loop 对齐建模、界面碰撞检测和 exit vector 识别等功能。通过将新底物的局部结构对齐到模板三元复合物，并计算与 CRBN 或其他蛋白界面的原子距离分布，可以初步评估新复合物是否存在严重空间冲突。进一步结合配体暴露原子与周边环境，可识别可能适合作为连接臂或化学修饰位点的出口向量。这些功能虽偏应用导向，但直接服务于先导分子的结构优化。

## 十、第五章正文草稿：系统实现与工程化

### 5.1 系统实现概述

GLINT 采用 Python 实现，并以 PyMOL 插件形式运行。系统核心代码位于 `glint/` 目录下，按照“算法模块-依赖封装-图形界面-工具支持”的方式组织。其中，入口模块负责命令注册、环境初始化与 Conda 运行时路径注入，以解决 PyMOL 嵌入式解释器与外部包环境隔离的问题。

### 5.2 命令层与 GUI 层解耦

系统没有将核心逻辑直接写入界面事件处理函数，而是优先以命令式接口暴露各分析能力，再由 GUI 调用这些接口完成交互式封装。这种设计使得同一功能既可通过 PyMOL 命令行批量调用，也可通过图形界面供非编程用户使用，有利于测试、复用和后续自动化扩展。

### 5.3 外部科学软件的集成策略

对于 Vina、HADDOCK3、APBS/PDB2PQR 和 FoldX 等工具，系统统一采用“检测-封装-降级”的集成路线。首先，环境检测模块通过 PATH、Conda 前缀、常见安装路径和平台特定目录对可执行文件进行搜索；其次，对每类工具分别封装最小可用调用流程，例如自动准备输入文件、生成配置文件、调用命令并解析结果；最后，在依赖缺失时提供错误引导、轻量替代模式或云端/手动安装建议。该策略兼顾了科学计算结果的可信度与终端用户的可用性。

### 5.4 跨平台兼容与环境自检

PyMOL 插件在跨平台分发时常见问题包括 Python 版本不一致、Qt 绑定冲突、Conda 环境不可见以及外部可执行文件路径差异。为解决这些问题，系统实现了环境检测和自动配置模块，可对子依赖包、Qt 图形库和科学软件进行分步检查，并将高风险依赖测试放在子进程中执行，以避免主进程崩溃。Qt 适配层进一步屏蔽了 PyQt5、PyQt6、PySide2 和 PySide6 之间的 API 差异。

### 5.5 安装与分发设计

考虑到目标用户群体未必具备熟练的软件部署能力，系统除了提供源码安装方式外，还设计了 macOS 与 Windows 的安装器脚本。安装器负责 Conda 环境引导、依赖安装、插件文件部署和安装后验证。对于某些无法在 Windows 原生稳定运行的计算引擎，项目明确采取“可信集成而非底层重写”的工程原则，避免以牺牲物理可靠性换取表面上的一键安装体验。

## 十二、可直接使用的“本文贡献”段落

本文围绕分子胶发现过程中“候选底物难识别、三元界面难评价、分析流程难贯通”的问题，设计并实现了一套结构计算与可视化一体化框架 GLINT。该框架以分子胶诱导三元复合物为核心分析对象，统一组织了 G-loop 结构模板匹配、蛋白口袋检测、表面相似性与互补性分析、相互作用识别、约束驱动三元建模以及综合评价等模块。与传统分散式分析流程相比，本文工作强调从任务角度组织算法和软件，而非简单拼接通用工具，从而提升了分子胶研究中结构分析的连续性、可解释性与可复现性。

## 十三、可直接使用的“不足与展望”段落

尽管本文构建的 GLINT 框架实现了面向分子胶发现的多模块集成，但仍存在若干限制。首先，部分分析模块目前仍基于经验阈值和规则系统，尚未在大规模标准化数据集上完成系统参数学习。其次，外部科学软件的可用性仍受平台与安装环境约束，尤其是在 Windows 环境下，部分高级功能依赖降级路径或替代工作流。再次，当前综合评价模块更多强调结构可解释性，尚未与大规模实验活性数据结合建立监督式预测模型。未来工作可沿三个方向推进：一是构建标准化分子胶三元复合物数据库与 benchmark；二是将本文提取的多维结构特征与图神经网络、三维几何深度学习模型结合；三是进一步扩展到更多 E3 连接酶家族和非 CRBN 场景，提高框架的适用范围。
