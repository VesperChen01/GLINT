# ADR-003: 拒绝用 C++ 自研重写科学计算底层依赖

**状态（Status）**: accepted  
**日期（Date）**: 2025-03  
**关联 ADR**: ADR-001 (Haddock3 Web Server 降级), ADR-002 (外部二进制引导安装策略)

---

## 背景（Context）

GLINT 在 Windows 平台下无法原生运行 HADDOCK3、APBS、AutoDock Vina 等科学计算工具，因为这些工具缺乏官方 Windows 原生预编译包，或深度依赖 POSIX 底层机制。

为此，曾有工程提案提出：**能否直接用 C++ 自行重写这些工具的核心计算逻辑**，以彻底消除对外部依赖的需求？本 ADR 对该提案作出明确的技术评估。

---

## 决策（Decision）

**拒绝通过自研 C++ 代码来替换或重实现 HADDOCK3、AutoDock Vina、APBS 等科学计算底层依赖。**

---

## 拒绝理由（Rationale）

### 1. 代码规模与历史沉淀量级不可比拟

| 工具 | 底层核心 | 代码规模 | 研发历史 |
|------|---------|---------|---------|
| HADDOCK3 | CNS（Crystallography & NMR System）| ~30 万行 Fortran/C | 约 30 年 |
| AutoDock Vina | 自定义分子对接引擎 | ~5 万行 C++ | 约 15 年 |
| APBS | 泊松-玻尔兹曼方程数值求解器 | ~10 万行 C | 约 20 年 |

这类软件经过数十年科研迭代、全球同行评审和大量真实生物数据验证。任何仓促的 C++ 自研替代版本，在短期内不可能达到同等计算精度与数值稳定性。

### 2. 科研软件的核心价值在于力场参数，而非代码本身

分子对接与静电势计算的精度由**经验力场参数（Force Field Parameters）**决定，而非算法代码。这些参数：

- 由各工具发布团队使用千万级实验晶体结构拟合优化；
- 部分参数（如 CNS 用到的 PARALLHDG 力场）为闭源学术资产；
- 自研替代版本若使用错误或粗糙的参数，将导致完全不可信的计算结果。

### 3. 工程成本与预期收益严重倒挂

- **工程成本**：以 HADDOCK3 为例，其底层 CNS 引擎的 C++ 完全重写，保守估计需要 **5～10 人年**；
- **预期收益**：仅为消除一个平台的安装摩擦，而现有替代方案（Web Server 降级、手动引导安装）的工程成本不足 **1 人周**；
- **风险放大**：自研版本一旦产出错误结果，将动摇用户对整个 GLINT 工具链的信任。

### 4. 违背开源科学软件的协作精神

GLINT 的定位是科学计算工具的**集成与可视化平台**，而非科学计算引擎的重写实现。拥抱成熟的上游工具，聚焦集成层的工程质量，才是项目应当投入的方向。

---

## 确立的标准处理方案（Established Standards）

针对 Windows 下此类科学计算依赖无法原生运行的情况，项目固化如下标准处理路径：

| 优先级 | 方案 | 适用场景 |
|--------|------|---------|
| P1 | **Web Server 云端降级** | 工具官方提供免费 Web 服务（如 HADDOCK3 Web Server） |
| P2 | **GUI 引导手动安装** | 工具提供官方 Windows `.exe`（如 Vina、APBS、FoldX） |
| 禁止 | **自研重写底层计算引擎** | 任何情况下均不允许 |

---

## 后果（Consequences）

- **正面**：工程资源聚焦在集成层，规避科研计算引擎重写的高风险；用户体验通过友好的降级引导得到保障。
- **负面**：Windows 用户在无网络或无法使用 Web Server 的极端场景下，部分功能不可用；这被视为可接受的平台限制，应在用户文档中明确说明。
- **约束**：所有新增科学计算功能模块，在引入新的外部二进制依赖前，须先评估其跨平台性，并按本 ADR 确立的标准提供降级方案。
